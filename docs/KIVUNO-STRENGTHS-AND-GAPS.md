## What the paired-machine milestone delivers

The runner hashes the transferable project files immediately before and after a command, including paths, bytes and Git executable modes. The signed result identifies the request, grant, project, task, source Git base when available, command digest, platform, architecture, OS release, runner Node version, exit code, timeout and output digest. The coordinator verifies the result on the authenticated machine connection and pins that runner's Ed25519 public key on first use. A replacement signing identity needs a new pairing. The runner's private key stays in its private data directory. A signature identifies the reporting machine. Anyone relying on that result still needs to trust the machine and the test.

Reviews displays each attempt. For each machine and command, the latest attempt must pass on the current worktree and task base. Editing a test input makes the pass stale. After checking the current worker files, integration captures the staged Git tree and compares it with the candidate about to land. A divergent target or a hook that changes the tree blocks integration. Human-initiated reruns synchronize the worktree and use the recorded command and original active grant. They spend no provider turn. Independent review and AEGIS approvals still apply when configured.

With updated endpoints, Reviews shows **awaiting result** while an attempt is outstanding and refreshes automatically. The runner saves the signed evidence before sending it and retains it until the coordinator records and acknowledges it. The same request can be delivered again within the live call. Its stable ID prevents a second execution. A reconnect or coordinator restart can recover completed evidence under the original active grant. If the runner stops before saving a signed outcome, Reviews reports an unconfirmed attempt and integration stays blocked.

Use **Refresh checks** after an external edit. **Rerun** shows the command for confirmation and starts a new attempt. **Export signed result** saves a manifest without raw logs. Another owner can check it with the following command and a runner key fingerprint obtained independently from the trusted coordinator. The verifier prints the signed outcome, including failures and timeouts.

```sh
node --import tsx scripts/verify-machine-check.ts paired-check.json TRUSTED_RUNNER_FINGERPRINT
```

The input digest covers regular, transferable repository files within the runner's size limits. Ignored dependencies, private files, OS state and arbitrary installed toolchains sit outside that digest. Keys and model sessions are outside the export. Runs before this protocol have no signed evidence. A Shared Sade task requiring a paired check needs a new witnessed run to integrate.

## Upstream code applied

Kivuno reuses QM's standalone canonical JSON serializer for command identities and signed evidence. Changing object key order leaves the identity intact, while changing ordered command arguments changes it. Kivuno keeps its own SQLite records, runner grants and Git merge rules. The upstream notice travels with the copied source in the desktop and cloud packages.

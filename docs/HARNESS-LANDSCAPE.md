# What Kivuno can learn from 100 harness projects

19 November 2026. A shared room where people bring their own CLI agents is already available in Commonly. Lody shares conversations across machines, and HumanLayer connects team plans and reviews to agents on the team's own hosts. A better test of Kivuno's value is whether one person can lend another a narrowly authorized check, lose the connection, and later show a reviewer exactly which patch passed. Kivuno already has the signed receipt, the runner outbox and the integration gate to make that test possible. [Commonly](https://github.com/Team-Commonly/commonly/tree/448347a6cbf118caafcccfcfb9dd95ddd15d4465) · [Lody](https://github.com/LodyAI/Lody/tree/1c2a979cb6a95edf0a175690104ca20296ade67a) · [HumanLayer](https://github.com/humanlayer/humanlayer/tree/2f5b58d3dfd18b13f4456b67ab0787df44233231) · [Kivuno's check and recovery model](KIVUNO-STRENGTHS-AND-GAPS.md)

## Changes made in Kivuno

1. **An external teammate can catch up in a busy workspace.** Previously, `mesh_wait` examined only the most recent 1,000 messages across all projects. Traffic in other rooms could bury a waiting teammate's next message until the 25-second timeout. Codeg explicitly detects when its recent-event buffer cannot answer a replay request. Kivuno already has the full history in SQLite, so the wait now checks the latest sequence in the authorized project. Reading, counting unread messages and checking an acknowledgement use the same project index. A page and its delivery boundary now share a transaction. QM's session-scoped sequence queries informed this change. [Codeg replay boundary](https://github.com/spacering-net/codeg/blob/b457eca0be6fa1269123ce8dbc46f236289886dd/src-tauri/src/acp/event_stream.rs#L161) · [QM session queries](https://github.com/yc-software/qm/blob/7d552d94d23db8f83d1aa247e488b465fdaace4c/src/sessions/session-items.ts#L90) · [Kivuno external wait](../server/external-provider.ts) · [Kivuno inbox](../server/mesh.ts)

2. **A chat retry resolves to one message, including when it changes an allowance.** HarnessRouter checks a retry key before provisioning and rejects a different request under that key. Meldwork scopes its channel delivery keys to a connection. Kivuno now looks up the human's request ID inside the same SQLite write transaction as the message and its effects. The key belongs to one project. Newly recorded messages check the redacted text, reply, task and explicit mention set on replay. The lookup uses a partial index. Older messages still compare the saved text, reply and task. They predate the distinction between explicit and inferred mentions. [HarnessRouter retry contract](https://github.com/HarnessRouter/harnessrouter/blob/c9d101a9c9a75c41f5be772c61e4d1e16709b907/gateway/tests/test_harness_idempotency.py#L51) · [Meldwork delivery identity](https://github.com/Ryder-Sun/Meldwork/blob/db9b6c84cbb1c86f3e3facf3cbebdcd6f1f79397/desktop/src/channels/channel-inbox-store.cjs#L74) · [Kivuno submission](../server/human-chat.ts)

3. **Shared Groups can tell when a full page is the last page.** Previously, a group with exactly 100 remaining messages returned all 100 and told the desktop to poll again in 200 ms. The service now asks SQLite for one extra row and returns at most 100. Only a real next row triggers the fast catch-up poll. Omnigent uses this same boundary in its conversation store. [Omnigent pagination](https://github.com/omnigent-ai/omnigent/blob/11cafae8530cccd391c66aecfd5e1904ff9382df/omnigent/stores/conversation_store/sqlalchemy_store.py#L3279) · [Kivuno group reads](../server/collaboration.ts)

These changes use Kivuno's existing TypeScript runtime and SQLite store. They add three message indexes and one optional record field. Existing global cursors survive an upgrade. The first opening of a large existing database will build the indexes. [Store implementation](../server/store.ts) · [Migration and delivery tests](../tests/mesh.test.ts)

## What the measurements cover

On Windows with Node 24.22.1, the same benchmark opened an in-memory workspace, inserted 40,000 messages interleaved across 20 projects and read a late page of 20. It checked the first returned sequence and total unread count on every read. Each process also timed ordinary appends to another project. There were five warm-ups and 31 timed operations per measurement, with three alternating baseline and changed runs. The table shows the median of those three medians. [Reproducible benchmark](../scripts/benchmark-room-history.ts) · [Baseline revision](https://github.com/dakiemdarktharr/WWW/tree/bb1321a272b6a99e96bbd019fac268b6ffe5aa64)

| Operation                                         |  Baseline |  Changed |
| ------------------------------------------------- | --------: | -------: |
| Local mesh room page, including unread count      | 87.287 ms | 0.302 ms |
| Allocate a global sequence and append one message | 38.903 ms | 0.031 ms |

Run `node --import tsx scripts/benchmark-room-history.ts` from the checkout. To repeat the baseline, run the same script in the baseline checkout. SQLite's query plan used the project/sequence index for the page and the global sequence index for the append. Network transport, disk durability, concurrent model activity and first-open index creation fall outside the timed operations.

The regression cases include 1,001 unrelated messages after a waiting project's unread message, mixed old and new sequence records, a foreign cursor, replayed redacted content, changed routing, and a final page of exactly 100. In a separate file-backed concurrency check, four workers submitted the same key simultaneously in each of three rounds. Each round produced one stored message and four identical response IDs. [External wait regression](../tests/external-provider.test.ts) · [Human-chat regressions](../tests/human-chat.test.ts) · [Shared Groups regressions](../tests/collaboration.test.ts)

## Where to invest next

1. **Explain eligibility before a team spends a turn.** Scion represents each capability with a support level and an optional reason. Kivuno exposes runner recovery support today, but a team also needs to know whose grant is missing, whether it is read-only, whether it expired, and whether the configured runner can execute this project's check. Have the grant screen and agent tool use one project-scoped decision. Acceptance test: two owners, two projects, an expired grant and an older runner. Both surfaces must identify the same actionable blocker without disclosing the other project's machines. [Scion capability model](https://github.com/GoogleCloudPlatform/scion/blob/993630cca4ace7bdf749015393a893ff5ae8057d/pkg/api/harness_capabilities.go#L17) · [Kivuno machine tools](../server/machine-tools.ts) · [Current group grant UI](../src/SharedGroups.tsx)

2. **Bind a team's acceptance criterion to an immutable check recipe.** SoduWork retrieves a specific artifact version for acceptance and verifies its digest. Kivuno binds a result to the exact transferable files and command, but a successful command can still be the wrong test for the stated requirement. Let the granting owner approve a named recipe and show its version, criterion and expected outcome in Reviews. Acceptance test: editing the recipe or the patch makes the previous result stale, while retrying delivery of an identical signed result runs no command. [SoduWork acceptance bundle](https://github.com/mdiri-ai/SoduWork/blob/709702daaa91c6866c1046c1b37f2a63c7c42123/client/main/pi-session/acceptance-bundle.js#L20) · [Kivuno check gate](../server/machine-checks.ts)

3. **Measure returning to a decision across two owners.** Commonly tests summarizing missed work by pod and author. Paseo records why a client has to reload a snapshot. DeepSeek Harness benchmarks reconnect under a long unfinished stream. Compare Kivuno with an ordinary pull request plus CI and with a shared-agent room. Give each pair the same changed patch, disconnect and review decision. Record setup time, time to the correct decision, duplicated commands and stale approvals. Keep unread, delivered and acknowledged distinct when presenting a catch-up summary. [Commonly missed-message test](https://github.com/Team-Commonly/commonly/blob/448347a6cbf118caafcccfcfb9dd95ddd15d4465/backend/__tests__/service/messageByOthersSince.realPg.test.js#L50) · [Paseo cursor recovery](https://github.com/getpaseo/paseo/blob/68cfad2c8a482bc9fc8901d8bdd9d9395cc56f8e/packages/server/src/server/directory-sync/internal/versioned-collection.ts#L92) · [DeepSeek reconnect benchmark](https://github.com/deepseek-ai/deepseek-harness/blob/2e39e70496aa02986ca6a820c5d497e816b69d7e/benchmarks/active-stream-reconnect/reconnect.bench.client.ts#L15)

One implementation worth keeping is Kivuno's token check when releasing a task lease. AX documents that after a prolonged PostgreSQL lock renewal failure the old worker may still be running when its lease expires. Kivuno's paired-command recovery needs the original request identity and a saved receipt to decide what happened. A lease timeout alone cannot establish whether a command finished. [AX lock design](https://github.com/google/ax/blob/af62e9da5df390495151ac0c9390559ed09c1be9/internal/store/postgres/lock.go#L64) · [Kivuno runner outbox](../server/machine-check-outbox.ts)

## Coverage and repository notes

All 100 supplied URLs resolved to downloadable default-branch snapshots. The archive inventory covered 719,546 regular files. The automated pass read 641,848 source, configuration and documentation files selected by extension and size, and searched implementation files for sequence queries, indexes, reconnect, worktrees, approvals and dispatch. It skipped binaries, files over 1.4 MB and common vendor, build, generated and fixture paths. I used project documentation for the breadth comparison and read the relevant implementations and tests for the adaptations. Runtime and performance results in this report are from Kivuno.
